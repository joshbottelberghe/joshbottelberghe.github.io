cachegrid

Distributed cache-compute, built in the open.

A small Go library I'm building: memoize expensive deterministic work, shard it across nodes by consistent hashing, and replicate each shard so it stays available when a node leaves. It came out of the fractal cache on the live-services page, where you can see it running for real. This page is the "how it works," and a log of building it. It's early — a good start, not a 1.0.

Two primitives

Cache[K,V]a concurrency-safe LRU that memoizes GetOrCompute(key, fn) and measures the recompute it avoids
Ringconsistent hashing with a replication factor: a key maps to a stable set of nodes, primary first
Clusterroutes Get across nodes over a Transport, failing over to a replica when a node is down

The ring, live

Consistent hashing places nodes and keys on a circle. A key belongs to the nodes clockwise from its position. Add or remove a node and only the keys near it move — roughly 1/N — instead of the whole keyspace reshuffling. Each node also sits at several positions (virtual nodes) so the load spreads evenly. See it running

The fractal cache is cachegrid in production: each Mandelbrot tile is sharded to a compute pod by this exact ring, replicated, and cached in two phases. Kill a pod and its tiles fail over to the replica with no downtime. This page is the theory; that page is the practice.
