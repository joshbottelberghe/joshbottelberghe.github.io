Endpoint pooling

Several agents, one address, balanced by the edge — and each one caps its own load.

My gateway runs as several identical agents that all dial out and claim the same ngrok endpoint (joshbottelberghe.ngrok.app). ngrok's edge load-balances across them — no load balancer for me to run. Each agent also rate-limits itself (~600 req/min), so the pool's total capacity is that cap times the number of live agents. This page samples the pool over a rolling 5-second window: it fires real requests, tags each response with the agent that served it, and reports the live distribution and — when you push past the cap — how much each agent is shedding as 429 Too Many Requests.

              ┌─▶ agent A ─┐
your browser ─▶ ngrok edge ─┼─▶ agent B ─┼─▶ (one answers; over its cap → 429)
              └─▶ agent C ─┘
      kill an agent → its share is picked up by the rest, no downtime
      push too hard → each agent caps at ~600 rpm, excess comes back 429

Each bar is one agent's share of the last 5 seconds of served traffic; the red sliver is what that agent threw back as 429. I scale the pool up and down (and kill agents) from my desktop with systemctl. Under the cap, load spreads evenly and nothing is throttled; drag the slider past ~30 req/s and you'll watch each agent hit its own limit and start shedding — the pods stay protected and balanced instead of falling over.
